# Skaperverksted

Part of the [master specification](../../DESIGNPORTEN_MASTER.md). Covers the workspace, the canvas and grid, the shared editor model, Signgen, the lamp generator, the articulated dragon generator and the future ecosystem. Domain types are in [technical-architecture.md](../architecture/technical-architecture.md#domain-model).

Skaperverksted is one of the most important parts of Designporten. Moving into it is moving **from the showroom into the workshop**. It must feel like a genuine creative application in the browser, borrowing the interaction language of CAD, graphics and 3D tools without copying any one of them, while staying understandable to people who have never used such tools.

It is **not** "a form on the left and a preview on the right".

## Workspace

### Layout (desktop, ≥1024 px)

```
┌──────────────────────────────────────────────────────────────────────┐
│ Workshop bar: logo · generator · project name · undo/redo · save ·   │
│               2D/3D · Eksporter / Bestill                            │
├────┬───────────────────────────────────────────────────────┬─────────┤
│Tool│                                                       │Inspector│
│rail│                CANVAS (the object is the focus)       │(context)│
│    │   floating toolbar near selection                     │         │
│    │                                                       │         │
│    │ ┌Layers (floating, collapsible)┐        view cube (3D)│         │
├────┴───────────────────────────────────────────────────────┴─────────┤
│ Status bar: object size W × H × D mm · layer count · zoom · est. weight │
└──────────────────────────────────────────────────────────────────────┘
```

- **Tool rail** (left, narrow, icons + labels on hover/focus): select, text, SVG/image, shapes, profile (Bézier), zoom, pan, measure. Generator-specific tools are added by the generator.
- **Canvas** fills all remaining space. The designed object is the visual focus; chrome is quiet.
- **Floating contextual toolbar** appears near the selected object with the most common actions (duplicate, delete, align, arrange, lock).
- **Layers panel** floats over the canvas's left edge and can collapse. It is the physical construction list.
- **Inspector** (right) shows properties of the current selection: position, size, rotation, layer, height, colour/material, profile. With nothing selected it shows the project: build size, plate, material set.
- **Status bar** shows real dimensions and useful facts. Estimated weight/material only once the estimate is computed from geometry, never guessed.
- **Workshop bar** replaces the site header. «Eksporter / Bestill» is the single primary action. There is always a clear way back to the showroom.

### Visual language

- Graphite workshop palette (`--verksted`, `--grafitt`), Archivo for UI text, IBM Plex Mono for all values and units.
- Lilla = selection and active state. Cyan = measurement, guides, snapping indicators and the active tool on dark. The user's material colours are the only saturated colour on the object.
- Panels: 4 px radius, 1 px hairlines, no glass, no shadows beyond a subtle lift for floating panels.
- Dense but calm: 12–13 px mono values, 14 px labels, 32 px control height (44 px on touch).

### Panel system and workspaces (Sign Forge; other generators opt in)

A generator that lists `ui.Paneler` gets dockable panels on screens of 1024 px and up (the shell code is in `shell/paneler/`; generators without it keep the fixed left panel and inspector, and small screens keep the bottom sheets for everyone).

- **Panels** are `PanelDef` entries (id, name, component). Sign Forge has **Lag**, **Egenskaper**, **Profil**, **Transform**, **Justér**, **Historikk** and **Produksjon**; more come with their phases (see below). CSV is **not** a panel: it is its own workflow.
- **Groups.** A panel lives in a group; a group holds one or more panels as tabs and sits in a dock column (left or right of the canvas) or floats over the canvas. Dock columns stack groups vertically and have draggable borders (width and height); floating groups resize from all edges and corners.
- **Drag a group header** to float it, dock it (at the edge or between groups: a thin line shows where) or drop it on another group to make tabs. Dragging a **tab** takes that panel out of the group. The panel menu (⋯ in every header) does the same without dragging (dock left or right, make floating, detach a tab, minimise, close), so the layout can be changed with keyboard only; borders can be moved with the arrow keys.
- **Minimise** collapses a group to its header (a single panel is minimised alone; a tab group as a whole). **Close** removes a panel; **Paneler** in the workshop bar shows and hides panels again and puts them where the first workspace has them.
- **Workspaces** are only panel arrangements: **Enkel** (Lag left, Egenskaper right), **Design** (adds Historikk), **Produksjon** (adds Produksjon) and **Egendefinert** (whatever the user arranged last). A manual change moves the user to Egendefinert; the user can save the current arrangement under a name and delete it again. Narrow desktop windows (< 1280 px) get single-dock versions of the ready-made ones.
- **Storage** is per generator in the browser (`dp-verksted:paneler:<id>`, versioned). A stored layout is repaired against today's panels when read (unknown panels go, new ones appear where the first workspace has them) and falls back to Enkel if damaged. Floating panels are kept inside the window.
- **Tool rail** (Sign Forge): icon only, no permanent labels (small screens keep labels). A hint with the name appears after a short hover and adds the description and shortcut after about three seconds; keyboard focus shows it at once; Esc dismisses it. Icons come from `shell/ikoner.tsx`, one entry per icon: Sivert's own 92-icon set ([signgen-ikoner](signgen-ikoner/README.md)), inlined as SVG so the UI controls size, colour and state, and swappable one by one without touching the toolbar. The few icons the set lacks (rectangle, ellipse, polygon, hole, decoration, panel chrome) are temporary line icons. **Former** is one tool for rectangle, ellipse and polygon (click again, right-click, long press or ↓ opens the list; R, E and P still pick a shape directly).
- **Number fields** keep typing and the arrow keys and get a **scrubber**: while the field is hovered or focused, a short millimetre scale appears along its bottom edge with a triangle that can be dragged (Shift = fine). One drag is one undo step. It is hidden on touch screens.

The larger Sign Forge UI update (Sivert, 2026-10-06) is delivered in phases, each its own change; the plan and data model are in the project folder `sign-forge-ui/plan.md`: 1 workspace and panels (this section), 2 layers panel and per-layer cross-section profile (done: see «Layers panel» and «Side profile and Bézier editing»), 3 drawing and precision (3a rulers, guides, snapping, Transform and Justér: see «Canvas»; 3b shapes with the mouse wheel, pen with Space, Paint and the boolean bar: see «Drawing: shapes, pen, Paint and the boolean bar»), 4 filament registry, colour profiles and fonts, 5 start page, templates and guest saves, 6 CSV workflow with master, instances and overrides.

- **Transform** (panel). Position of the selection's centre, total width and height (with «Behold proporsjoner») and, for one object, rotation, as number fields with the scrubber. With several objects the box of the whole selection is used; the numbers are measured around the shape, not the plate.
- **Justér** (panel). Align (left, centre, right, top, middle, bottom) and distribute horizontally or vertically against the selection, the plate or a guide: *Utvalget* lines objects up with each other, *Plata* with the plate's edges (also for one object), *Linje* with the selected guide (along the guide's own direction only). Distribute spreads objects evenly between the outermost two (or the outermost guides / the plate's edges). The panel also holds the guide list.

### Tablet and mobile

- Canvas gets the maximum space. Panels become **bottom sheets** (Layers, Inspector, Library) opened from a compact bottom toolbar. Only one sheet is open at a time; it snaps to peek / half / full.
- Touch gestures: one finger selects and moves, two fingers pan and pinch-zoom, two-finger rotate on a selected object rotates it (snapping to 15°), long press opens the context menu.
- Numeric inputs remain available in the Inspector sheet for precision.
- Nothing essential is removed on mobile. If a function genuinely needs a larger screen (for example batch plate layout), the tool says so plainly and offers to continue on a larger screen; it never silently breaks.

## Canvas and adaptive measurement grid

- **No photographic background.** A neutral graphite (or a light technical variant for 2D printing previews) with the grid.
- **Real units.** The canvas knows millimetres. 100 % zoom renders 1 mm as one CSS millimetre (≈3.78 CSS px), so a sign at 100 % is roughly its real size on a typical screen; the status bar shows the current zoom.
- **Adaptive grid:** major and minor lines chosen from the sequence 1 · 2 · 5 · 10 · 20 · 50 · 100 · 200 mm so that minor lines stay ≥ 8 screen px apart. Zoomed out the user sees centimetres (10 mm major, labelled in cm); zooming in reveals millimetre subdivisions, then 0.5/0.1 mm. Minor lines fade in with zoom rather than popping.
- **Rulers** along the top and left edges in mm, with the selection's extent highlighted on the rulers.
- **Guides (Sign Forge).** Drag out of a ruler to make a guide (the top ruler makes a horizontal one, the left ruler a vertical one); drop it back on its ruler to remove it. Click a guide with the select tool to select it: a small bar next to it has its position (a number field), **Lås** (a locked guide cannot be dragged, moved with the arrows or deleted) and **Slett**; the arrow keys move it (Shift = 10 ×), Delete removes it. Guides are saved with the project (`Dokument.hjelpelinjer`, optional, so old projects open unchanged), have their own undo steps, and **never reach the 3D model or any export**. The **Hjelpelinjer** tool button hides and shows them all (a workspace setting, not part of the project); the Justér panel lists them with position, lock and delete, and can add one by number. Objects win over guides when both are under the pointer.
- **Snap targets.** The Snap button switches snapping on or off; right-click or long press opens a list of what it snaps to: **Rutenett**, **Hjelpelinjer**, **Kanter og hjørner**, **Midtpunkter** (remembered in the browser, per generator). Alt disables snapping while held.
- **Shift = 45°.** Holding Shift while moving an object locks the movement to the nearest 45° direction from where it started; while rotating it snaps to 45° steps. (Without Shift, rotating snaps to 15° when Snap is on.)
- **Build plate / bounds:** the printable area (from the printer profile) is drawn as a subtle outline; objects outside it are flagged.
- **Selection:** clear bounding box with handles; the active object is unmistakable; other objects stay fully visible but quieter when needed.
- **Snapping:** to grid, to other objects' edges and centres, to the plate centre, and to 15° rotation steps. Snap guides appear in cyan with the distance in mm. Holding Alt (or a toggle on touch) disables snapping temporarily. Snapping on/off is a visible toggle.
- **Measurement:** dimensions appear while dragging and resizing; a measure tool shows distances between points or objects.
- **Pan and zoom:** wheel/trackpad zoom to cursor, Space-drag or middle-drag to pan, `0` fit to object, `1` to 100 %, `+`/`−`.
- **Clutter control:** labels and guides appear only while relevant.

## Shared editor behaviour

| Behaviour | Rule |
|---|---|
| Undo / redo | Every model change is a command in the history; Ctrl/Cmd+Z, Shift+Ctrl/Cmd+Z; drags merge into one step |
| Selection | Click, Shift-click to add, drag-marquee, Ctrl/Cmd+A; Esc clears |
| Transform | Move (drag, arrows 1 mm, Shift+arrows 10 mm), scale (proportional by default, lock toggle), rotate |
| Duplicate / delete | Ctrl/Cmd+D, Delete/Backspace |
| Visibility / lock | Per object and per layer |
| Units | All values in mm with one decimal by default; inputs accept simple arithmetic («40+2.5») |
| 2D / 3D | One model, two views. 2D for layout and precision, 3D for form, height and colour. The view switch never loses selection. |
| Autosave | Local autosave of the current project (browser storage) so a reload never loses work. Server-side project saving comes with accounts. |
| Export / order | A review step opens on a preview of the build plate (the exported parts from above, to scale, in their colours, with the numbered filament slots) with the 3D model as a second tab, shows dimensions, parts, colours and printability warnings, then offers «Bestill» (adds to cart) and, subject to D-4, file export. 3MF files are placed on the plate as in the editor and carry a filament slot per colour for Bambu Studio / OrcaSlicer (`Metadata/model_settings.config`) |
| Keyboard | All tools and panels reachable; shortcuts listed in a help overlay (`?`); canvas objects selectable via the Layers panel for keyboard and screen-reader users |

## Signgen — 3D-printed sign generator

**Name:** Signgen. Norwegian descriptor: «skiltgenerator». Signgen makes **3D-printed signs and nameplates**. It does not make wooden signs; a wood-look filament is only a material option.

### Model

> SVG + TEXT + SHAPES → LAYERS → HEIGHTS → PROFILES → COLOURS → 3D MODEL

The user constructs the physical sign **layer by layer**. A layer is a physical slab of printed material with a height and a colour/material role; it contains one or more 2D objects whose union forms the layer's outline.

### Capabilities

MVP (Phase 3) and later (Phase 5) are marked. The architecture supports all of them from the start.

| Text objects with font selection (curated Open Font License fonts, loaded on demand) | 3 |
| SVG import (paths, basic shapes; text in SVG converted or rejected with a message) | 3 |
| Basic shapes (rectangle, rounded rectangle, ellipse, plate outlines, hanging hole) | 3 |
| Per-layer height (thickness) and Z position | 3 |
| X/Y position, scale, rotation per object | 3 |
| Colour/material per layer | 3 |
| Visibility, deletion, duplication | 3 |
| Snapping, dimensions in mm | 3 |
| 2D editing and 3D preview | 3 |
| Straight (vertical) extrusion | 3 |

### Text layers and outlines

Sivert, 2026-10-05. Text spread over many layers at different heights became hard to follow, so text has its own kind of layer, and the outlines around a text belong to it.

- **Text layer.** Text lives only in text layers, and text layers hold only text (vectors can join them, see [Decor](#decor-and-vectors)). A new text gets a text layer of its own (above the active layer) **unless a text layer is selected: then the text goes into that layer and is grouped with what is there** (Sivert, 2026-10-05). «+ Nytt lag → Tekstlag» makes an empty, separate text layer. Text layers can still be moved, hidden, locked and duplicated like other layers.
- **Grouping.** Several texts can be grouped in one text layer («Grupper tekst» with two or more texts selected); they then share its height, look and outlines, and the outlines follow all of them. Ungrouped texts are separate text layers and never affect each other's outlines. «Eget tekstlag» on a grouped text takes it out into a new text layer with a copy of the group's settings and outlines.
- **Dragging.** In the layers panel a text, or a whole text layer, can be dragged onto another text layer: it then joins that layer's group and gets its look, its outlines and its height. Dragging an object out of a group (the dashed zone «Slipp her for å ta det ut av gruppen») gives it a layer of its own: a text gets a text layer with a copy of the group's settings and outlines. The inspector's «Lag eller gruppe» list does the same without dragging (keyboard and touch). A layer emptied by this is removed, except the last one.
- **Outlines** («omriss»): a text layer has any number, listed inside out, each its own row in the layers panel. Choosing an outline row selects **only that outline**: the inspector shows its settings alone, with «Vis alle omrissene» to see them all. Each has a type, **fyll** (filled out to its width; closes holes such as the inside of «o» and the gaps between letters) or **omriss** (a ring that follows the edge), a width (at least **0.6 mm**), a gap from what is inside it, its own **height**, its own colour and corner style. Outlines never cover the text or each other; the text is always in the centre. Each outline is its own part in the model and the export.
- **Heights.** Text and outlines start at the text layer's Z. The text's height is the layer's height; changing it does not change the outlines. In the stack, the layer takes the height of its tallest part.
- **Text display.** The text **stands up** (default) or is **cut out** («Skåret ut»): no text part is printed, and the text is a hole through the outlines, so whatever is below shows through.
- **Influences** between layers work as before. A text layer acting on another layer acts with its text and its outlines together.
- The side profile applies to the text; outlines are straight. A layer's own Kontur stays for plain layers (and for text layers from older projects that already use it).
- Projects from before text layers open unchanged: layers that hold only text become text layers (their texts a group, no outlines). Text in a layer with shapes stays where it is, prints as before and is reported until the user moves it to a text layer.

### Start sign, colour profiles, new layers and holes

Sivert, 2026-10-05.

- **No base plate.** A new sign is one text layer with one filled outline, «Underlag», as its base (text 3 mm, base 2 mm). A plate is still possible as a layer of its own.
- **Colour profiles.** A sign has a colour profile (`parametre.farger`): the filaments the user has in the printer or can get. A new sign opens a **start window** to pick it: ready-made profiles (combinations from the catalogue, not confirmed stock) or the user's own, saved in this browser. A profile has **four colours by default**; colours can be added from the catalogue or removed. The colour pickers offer the profile first; picking a catalogue colour outside it adds it to the profile. «Endre fargeprofil» in the project inspector reopens the window; colours the new profile drops are swapped for the closest one in it. Projects from before profiles get the colours they already use.
- **New layers.** «+ Nytt lag» offers: **Rundt teksten** (a layer at the bottom shaped by every text layer and its outlines, 4 mm wider, through influences, so it follows the text), **SVG som ramme** (an SVG in a layer at the bottom, scaled to go round the sign), **SVG som pynt** (an SVG in a layer of its own above the active layer; also the tool rail's SVG button) and **Tomt lag**.
- **Hanging holes and eyes.** The hole tool's size is the inner diameter. Over the model (at least half the hole on it) it is a hole through every layer. Dragged off the model it becomes an **eye**: a ring (3 mm by default, at least 0.6 mm) round the hole, joined to the lowest layer, or to that layer's outermost outline when it is a text layer with outlines. An eye that does not touch the sign is reported. Holes need no layer of their own; when there is no plain layer they get one, «Hull og øyne», which takes no room in the stack.
- **CSV.** A field is «too long for the sign» only when the sign has a plate or frame (shapes in plain layers); text and outlines grow with the text.

### Decor and vectors

Sivert, 2026-10-05.

- **Gallery.** «Dekor» in the tool rail (and «+ Nytt lag → Dekor fra galleri») opens a gallery of 24 vector elements: star, heart, moon, sun, flower, fir, horse, unicorn, butterfly, cat, dog, fish, shark, rabbit, paw, rocket, crown, anchor, bolt, tractor, excavator, football, game controller and owl. They are icons from **Material Design Icons** (Pictogrammers, Apache License 2.0), taken from the open-source package, with the credit shown in the gallery. They are not drawn by Designporten. Sizes are 24 mm at a 24-unit grid; the shapes are copied into the project as ordinary vector paths.
- **Own vectors.** «Legg til egen vektor (SVG)» imports an SVG into the gallery. Own vectors are stored in this browser only (no accounts yet), can be removed and are never uploaded.
- **Holes.** A vector keeps its holes by default (the openings in a butterfly, the counters in a flower). In the inspector, «Hull i vektoren» can be set to **Fyll igjen** so only the silhouette remains. Overlapping paths use each path's own fill rule, so paths drawn as negative space cut as holes.
- **Placement.** Under «Legges» the user picks **I tekstlaget «X»** (default when a text layer exists: the vector is grouped with the text, so it shares the text layer's outlines, height and colour, and is placed beside the text group, 1.3 times the text height, between 10 and 40 mm) or **I eget lag** (a plain layer «Pynt» above the active layer; top right of the sign, a third of its height). A vector can be dragged between a text layer and a layer of its own at any time, or moved with the inspector's «Lag eller gruppe» list. A vector in a text layer joins the layer's union and is covered by its outlines like the letters; a «Kutter» vector cuts out of the text layer. Plain shapes (rectangles, ellipses) are not allowed in text layers.
- **Parts, masking and colours** (Sivert, 2026-10-05). An SVG with more than one part (a sheet of icons, a horse with a separate mane) opens the **part picker** instead of going straight onto the sign, from the tool rail's SVG button, «+ Nytt lag → SVG som pynt/ramme» and the gallery's «Legg til egen vektor». Every filled shape in the file is split into its separate pieces; a piece inside a hole of another (the disc in a flower, the pentagons in a ball) stays with the shape around it. Pieces are chosen by clicking, by dragging a frame (a piece is chosen when it lies wholly inside; Shift/Ctrl adds) or from the list under the drawing (checkbox and colour per part), which is the keyboard and touch way. **Masking:** «Behold bare de valgte», «Ta bort de valgte» and «Ta med alle igjen»; a part set to «Ikke med» is left out. **Colours:** each kept part gets a filament from the sign's colour profile; a file with several fills starts with the closest unused filament per fill, a file with one fill starts in the first colour. Where parts of different colours lie on top of each other the one painted later wins (an eye drawn over a head cuts the head), so each point is printed in one colour. Over 300 parts the file is split by shape only, and the picker says so.
- **Result.** «Legg på skiltet» puts the kept parts on the sign: one colour as an ordinary decoration (in the text layer or a layer of its own, as above); several colours as **one layer where every colour is an object with its own colour** (see «Farge per objekt» below), keeping their places relative to each other. A frame is one colour, so for a frame the picker only masks. «Lagre i galleriet» keeps the kept parts as the user's own vector under «Dine egne» **with their colours** (a vector with several colours is put on a sign in one layer with a colour per object, or in a text layer with a colour per object so the text's outlines go round all of it; in a CSV cell it becomes one colour). «Last ned SVG» writes the kept parts out as an SVG file in the chosen filament colours. Nothing is uploaded; own vectors stay in this browser.
- **Same level.** A layer can be set to «Samme nivå som laget under»: it starts at the same Z as the layer under it instead of on top of it (and the next layer stacks on the tallest of them). This is what lets coloured parts lie side by side as one flat picture; it works for any layers while «Stable lagene automatisk» is on. Picture layers are placed like other decorations (top right, a third of the sign's height, above the active layer), so a picture partly outside the sign hangs in the air until the user moves it or sets the layer's level; the existing check reports it.
- **Variable decor.** A vector can be a **batch field** («Batchfelt (dekor)» in the inspector), see Batch below.

### Filaments, the Fargeprofil panel and fonts

Sivert, 2026-10-06 (§16 to §20 of the Sign Forge prompt).

- **A colour is a filament.** Every layer, outline and object points at a filament id. The starting catalogue and the filaments the user adds are the same kind of thing (`Materiale` in `core/materialer.ts`): colour name, display colour, material, and optionally manufacturer, product series, article number (SKU), own name, physical spool, AMS slot (1 to 16) and notes. The catalogue ids are unchanged, so older projects need no migration. There is **no free RGB picker**.
- **Colours are shown as a swatch and a colour code, never as a name** (Sivert, 2026-10-07). Menus, lists, the profile panel, the export preview and the CSV views show the swatch and the hex code (`fargekode` in `core/materialer.ts`); the name stays only as a tooltip and screen-reader label. The filament list shows what else is known (type, manufacturer, AMS slot) beside the code, and the register search still finds a filament by its name.
- **Farge per objekt.** An object may have its own colour (`Objekt.materialId`, empty = the layer's). The layer's outline offset, height, profile and influences work on all of its objects together; `fargedeler` in `modell.ts` then splits the printed region by colour (the front-most object wins where colours overlap, the outline goes to the nearest colour, the rest keeps the layer's colour) and each colour is one part in the 3MF with its own filament slot. The colour profile, the CSV colour profile and `settPalett` map object colours like layer colours, and a CSV colour column can name a layer, an outline or an object. A shape in a vector that is given a colour of its own becomes an object in the same layer, not a new layer.
- **Fargepalett.** A colour is chosen from a grid of swatches (the profile's filaments); the hex code is shown with the swatch and under the grid, and the name only while hovering or as a screen-reader label. Visible text never defines a colour.
- **Lyst grensesnitt og horisont.** `flate: 'lys'` on the plug-in gives the workshop the light tokens (`.verksted.lys`); the work surfaces (`.lerret`, `.visning3d`) keep dark tokens and a vertical gradient (`--horisont-*`) with the horizon at about 60 %. The 2D canvas draws it with `horisontStopp` behind the grid, the plate takes `--bord`, and the 3D scene background is the same gradient as a texture.
- **Høyde på hull.** A hanging hole has an optional own height (`hullHoyde`, mm from the underside). Over the model it cuts only the layers that start below it (a layer it ends inside is cut whole); an eye becomes a ring of its own of that height, a separate part, so no other layer changes. Unset means through everything / as tall as the layer.
- **Panorering.** The hand is closed (`grabbing`) while Space or the wheel button is held, and open (`grab`) with the pan tool until dragged.
- **The profile is any size.** `parametre.farger` is the project's list of filament ids; the old four-colour default is only a default.
- **Clickable swatches.** A colour swatch that can be changed (the layer's and outline's colour in Egenskaper, an outline's swatch in the layers panel) opens a small menu of the profile's filaments; the last entry, «Flere filamenter …», opens the Fargeprofil panel (or the profile window on small screens).
- **Fargeprofil panel** (dockable, a tab next to Egenskaper): the project's colours with order, remove and «i bruk»; ready-made and own profiles; **colour groups** (named sets of filaments, browser only); the **registry** with search over name, manufacturer, series, material, SKU and notes, a manufacturer and a material filter; add, edit and delete your own filaments. The start and profile window can also add a filament.
- **Where it is kept.** Own filaments, groups and profiles live in this browser. The project carries a copy of the own filaments it uses (`parametre.filamenter`), so it opens with the same colours on another computer; the browser's copy wins when both exist.
- **No product catalogue.** Designporten has no authorised data for Bambu Lab, Polymaker, Prusament or others. The starting catalogue is the generic list (not confirmed stock); manufacturer names are only suggestions in the form. A real catalogue can be read in later as more `Materiale` entries.
- **Google Fonts.** The text inspector has «Flere fonter fra Google Fonts …»: search the families, pick a weight, add. Google's own list needs an API key, so the list and file addresses come from the open **Fontsource** mirror (api.fontsource.org, files from the jsDelivr CDN), Latin subset only (it has æ, ø, å) and WOFF/TTF (WOFF2 cannot be read). The font file is kept in the browser's font library and copied into the project that uses it (`parametre.fonter`), so the 3D model builds offline. The network is needed to add a font, not to use it.


### Start page, templates and guest storage

Sivert, 2026-10-06 (§21 to §23 of the Sign Forge prompt).

- **Start page.** A new sign opens a page with three large entries instead of an empty editor: **Tomt dokument** (on to the colour choice, then the editor), **Fra mal** (the template library) and **Fra CSV** (the colour choice, then a sign to use as the master, and the CSV window opens; a dedicated CSV workflow follows in a later phase). Esc starts an empty sign in the standard colours, so nobody is left without an editor. Closing the colour choice goes back to the page.
- **Templates** (`generatorer/signgen/maler.ts`). A template is a deep copy of a sign plus: name, description, visibility (**privat**, **gratis**, **kommersiell**), creator, owner, licence (words), price (only for commercial, NOK), credit line and usage rights. Only private templates in this browser exist; **there is no marketplace, no payment and no sharing**. The fields are stored so those can be added without changing the model. «Lagre som mal …» is in the Fil menu; «Nytt prosjekt fra mal …» asks first, because it replaces the open project.
- **Using a template** copies it into a new project (new id, named after the template, `parametre.malopphav` remembers the template, creator, licence and credit) and never changes the original. A template made from a project that came from a template does not inherit the source.
- **Shipped template.** One: «Navneskilt» from Designporten. Its licence says «Ikke avklart ennå» because no terms have been decided.
- **Guest storage.** Without an account one project per tool is kept in the browser. For Sign Forge it is deleted when it has not been opened for **more than 30 days**. Every opening and every autosave renews the time, so working in it keeps it; the check runs once when the tool opens, and a missing, unreadable or future time counts as «used now», so a clock or storage oddity never deletes a project. The user is told on the start page and in the Fil menu, warned on opening if it lay unused for 14 days or more, and told why if it was deleted. Downloading the project as a file («Lagre som fil») keeps it for good.


### Layers panel

The Layers panel makes the physical construction understandable. For every layer the user sees:

- what it contains (object thumbnails and names);
- its **physical height** (thickness, mm) and **Z range** (from–to, mm);
- its order in the stack, top to bottom, matching physical order;
- its **colour/material role** (swatch and material name);
- visibility and lock toggles;
- which objects belong to it (expand to list; drag objects between layers).
- for a text layer: its texts and its outlines (inside out), each outline with its type, width, height, colour and visibility, and «+ Omriss».

Phase 2 of the UI update (2026-10-07) refines the rows without changing what they do: a **thumbnail** of the layer's own shape in its colour (thinned outline of the region, functional geometry), visibility and lock as pack icons with names kept for screen readers (`aria-pressed`), **derived geometry as child rows** (outlines as before; a layer's influences are read-only rows «Kuttet av …» / «Utvidet med …» that follow their source layer), a **neutral selection** (lighter surface, no purple frame), **rename in place** (double-click, or in the menu; Enter saves, Esc cancels) and a **context menu** on right-click, the menu key or Shift+F10 (rename, edit profile, duplicate, hide, lock, move up and down, delete; arrow keys, Esc closes). Drag between layers is unchanged.

The stack diagram (an exploded side view) was removed at Sivert's request on 2026-10-05; Z ranges stay in each row. Selecting a layer highlights it in 3D.

### Editing vectors: points, curves, pen and repair

Sivert, 2026-10-05 («dobbeltklikke på svg og redigere de, legge til eller fjerne kurver … eget tegneverktøy slik som i Illustrator med penneverktøy … sette farger på modellen og slette kurver som danner en form … reparere vektorer som ikke er sluttet»).

- **Real curves are kept.** A vector's path data is read into paths of points with handles (`geometri/bane.ts`: lines, cubic and quadratic curves and arcs; arcs and quadratics become cubics). The gallery icons, imported SVGs, parts picked in the part picker, multi-colour sheets and the SVG download keep their curves when that gives the same shape as before (checked by comparing the regions; if not, for instance where a later-painted part cuts an earlier one, the part falls back to short lines, which can still be moved point by point). Polygon-only vectors (the star, the fir) are lines by nature.
- **Edit mode.** Double-click an SVG (or «Rediger kurver» in the floating bar or inspector) to edit its points. Anchors are squares (corners) or circles (smooth points); selected points show their handles. **Click** a point or curve to select, **Shift+click** to add, **drag a frame** round points to select several, **click inside a shape** to select it and drag to move it (holes follow). **Drag** a point, a handle or a curve (a curved piece bends so the point under the pointer follows; a straight piece moves with its ends). **Alt** on a handle breaks it from the other handle. **Double-click a curve** adds a point, **double-click a point** switches between corner and smooth. **Delete** removes selected points; with a curve piece selected it removes that piece (the path opens there); with a shape selected it removes the shape **with the holes inside it**; nothing selected does nothing. Arrow keys nudge the selected points 0.1 mm (Shift 1 mm). Esc clears the selection, a second Esc (or Enter, or «Ferdig») leaves. While dragging only the outline is previewed; the vector changes once, when the pointer is released, as one undo step.
- **Colour per shape.** With a shape selected, a filament from the sign's profile moves it to a vector in a layer of its own at the same level (see «Samme nivå»), named «navn · farge». A vector alone in its layer just changes the layer's colour. This is the same mechanism as colours in the part picker, so it prints as separate, touching parts.
- **Pen tool** (B). Click for a corner point, click and drag for a smooth point with handles (Alt: pull out only the next handle), click the first point to close, Enter or double-click to finish an open path, Backspace takes back the last point, Esc finishes or stops. The first path makes a vector («Tegning») where it was drawn, the next ones are added to it, and a path inside another is a **hole** (even-odd rule; «Baner inni hverandre» in the panel switches to one joined area). The pen also adds paths to a vector in edit mode.
- **Repair.** Paths that are not closed are shown dashed orange with rings at their ends, counted in the panel and in the inspector. A closed fill is still made from them (as SVG does), but «Reparer åpne baner» joins ends that lie within a distance (default 0.5 mm, set in the panel) — an end to the other end of the same path closes it, an end to another path's end joins the two — and «Vis hva som blir koblet» shows the planned joins in green first. «Lukk resten med rett linje» closes what is still open and drops loose single lines. «Lukk bane» closes the selected open paths by hand.
- **Gallery.** «Lagre i galleriet» in the panel keeps the edited vector under «Dine egne».
- **Limits.** Edit mode works in the 2D view and for unlocked vectors. Node type (corner/smooth) is remembered for the session and undo; after reloading it is read back from the handles. Vectors saved before this change as many short lines can only be edited point by point. Nothing here is test-printed.

### Drawing: shapes, pen, Paint and the boolean bar

- **Former** has rectangle, ellipse, **triangle** and polygon. While the button is down on a triangle or polygon, the **mouse wheel** (or ↑ ↓) adds or removes a side (3 to 24; scroll up = one more); the outline in the draft shows the real shape and the label says «5 sider · 24 × 22 mm». A triangle is a polygon with three sides, so it can be given more sides, and a polygon remembers its last number of sides. Afterwards «Antall sider» in Egenskaper does the same.
- **Pen.** Hold **Space** while placing a point (button down) to move the point itself instead of pulling out handles; let go to pull handles again. **Shift** locks the next segment (or the handle being pulled) to 45° from the point before it.
- **Paint** (F). Drag to paint a stroke freehand. The pointer path is thinned and simplified to a few control points; the stroke is a **centre line** (a smooth spline through them) with a **width profile** (the base width times a curve through *width points*) and a closed outline with round ends. The bar above the canvas sets what the next stroke uses: base width, ready-made profile (**Jevn**, **Penselstrøk** = 100 % → 160 % → 70 % → 0 %, **Spiss**) and **Smooth** (smoothing of the centre line). The finished stroke is a vector («Strek») that still knows its source: in Egenskaper you change the width, the profile (a graph with draggable points and, for the keyboard, a number field for the position and width of every point, with «+ Breddepunkt» and «Fjern»), Smooth and **Tupp** (taper: the start and the end tapering to nothing over a share of the stroke). **Gjør om til vektor** drops the source, so the outline's points can be edited like any vector. Editing the outline's points does the same. Loops that cross themselves are merged, so a stroke that crosses itself is one solid shape.
- **Boolean bar.** With two or more shapes or vectors selected, the bar under the selection has **Union**, **Subtract**, **Intersect** and **Exclude**. The selected objects are replaced by one vector, in the layer of the back-most one, in one undo step. Subtract removes everything in front from the back-most one; Exclude keeps what lies in an odd number of the shapes. Text, hanging holes and cutters are not combined (the bar is disabled with a reason in its tooltip); a result without area changes nothing.

- **Width on the canvas.** A selected Paint stroke shows its spline with a control across it for every width point (purple dot on the edge, cyan dot on the spline). Drag a control across the spline to make that part narrower or wider (the width is the pointer's distance from the spline, both sides; one drag is one undo step). Click the spline to add a width point there, double-click an inner point to remove it (the two ends stay; at most 8 points). The list in Egenskaper stays as the keyboard alternative. Neither edge of the outline is edited by hand.
- **Shift in Paint.** Holding Shift while painting locks the next movement to 45° from the previous anchor.
- **The boolean bar is icon only.** Union, Subtract, Intersect and Exclude show a short description on hover (or focus) and the reason when a button cannot be used (for example «Velg minst to former»).

### Side profile and Bézier editing

A layer is not limited to a vertical extrusion. Its **side profile** describes how the edge rises from the layer's bottom (Z₀) to its top (Z₁) as an inset from the layer's outline.

- **Profil panel** (Sign Forge, wide screens; on small screens the same editor sits under «Sideprofil» in Egenskaper). It follows the selected layer. Egenskaper has a button that opens it as a tab next to Egenskaper; the Design workspace has it there from the start.
- **Cross-section editor.** A graph with the inset from the outline (mm, outside left) across and the layer's thickness up, limited to the layer: nothing can leave the layer's bottom and top. **Anchors sit only on the bottom edge and the top edge** and move sideways along them (or by the «Bunnkant» and «Toppkant» fields, in mm, with the scrubber). The wall between the two anchors has one shape: **Rett**, **Bue ut**, **Bue inn**, **S-kurve**, **Trapp** (steps, count adjustable), the older **Avrundet kant** and **Knekk**, or **Egendefinert kurve**, where the Bézier handles of the wall appear, can be dragged, and a point can be made smooth or a corner. Moving an anchor on a ready-made shape rebuilds the shape around the anchors, so «Bue ut» stays a bue. A wall rises in one direction in print, so a layer has exactly one wall segment; the bottom and top edges are flat.
- **Older profiles** from before this phase load unchanged. Ones with points between the edges (chamfer, rounded edge, steps, hand-made curves) keep them; they can still be moved or removed and the panel says so, but new points are never added between the edges.
- **Support from the layer below** is drawn as a read-only strip under the graph, from the layer under it (its own top edge and profile counted): «byggeplaten» when the layer sits on the plate, hatched red where the bottom edge rests on nothing, with a dashed line at the inset where it starts to rest fully. The text says how far the bottom hangs out and how deep it must start. The layer below is never edited from here. The same footprints drive the «henger i lufta» warning, so a layer resting on a rounded top is flagged.
- **This is geometry, not a visual effect.** The profile produces real sloped/curved walls in the mesh and in the export (slabs at the print layer height), and the 3D preview shows exactly what will print. Warnings: overhang beyond the material's limit; a profile wider than the shape tolerates.

### Batch (CSV)

- A **master sign** marks one or more text objects as **fields** (for example `navn`), and vectors as **decor fields** (for example `dekor`).
- Import a CSV; columns map to fields; the tool previews every row and flags rows whose text overflows the sign.
- Generates one sign per row as variants of the master design.
- **Decor variables.** A decor field takes the name of a gallery element or one of the user's own vectors in the cell («stjerne», «Enhjørning»; case and æ/ø/å insensitive). An empty cell, «-», «ingen» or «nei» hides the decor on that sign. An unknown name is a problem on that row («ukjent dekor …»), not a silent fallback. The decor keeps its size and position from the master sign.
- **Group spacing.** Two or more texts (or vectors) that sit side by side or stacked, where at least one is a field, keep the **same gap on every sign**: first and last name end up equally far apart whatever the names are (option «Hold avstanden mellom tekstene som hører sammen lik på alle skilt», on by default when such a group exists). The texts may be in one text layer or in several. The gap is measured on the master sign; side by side it is the visible gap between the printed letters, stacked it is the gap between the line boxes, so baselines keep a steady pitch whatever ascenders and descenders the names have. The order stays; the group keeps its centre and grows outwards from it. A decoration in the group that a row leaves out (empty cell or «ingen») takes no room, and the names keep their own gap.
- **Holes follow the name** (Sivert, 2026-10-05: «hull må ha et referansepunkt … lik avstandsmotor som med navnene»). A hanging hole or an eye has a reference to the name: the **box of the printed letters** (across) and the lines (down) of everything in the text layers. On the master sign the tool measures which side the hole is furthest out on (left, right, above, below), its clear gap to that edge and its place across the name. On every sign in the series the hole is placed at that same gap on the same side, so it follows the name when the name grows and never ends up standing alone (option «Hold hull og øyne like langt fra navnet på alle skilt», on by default). Per hole, «Plass når navnet er et felt i CSV»: **Automatisk** (follows the name on a sign whose size comes from the text, i.e. outlines; keeps its place on a fixed plate or frame, since that does not grow), **Følger navnet** or **Fast plass**. The inspector shows the reference («8 mm til venstre for bokstavene») and a field «Avstand fra navnet» that moves the hole. This is a batch rule; editing the text on the sign itself does not move the hole.
- **Preview.** The plates step shows the real **build plate** with the signs as they will lie in the 3MF files, from the same meshes as the export, numbered by CSV row, with the filament list. The plate packing uses each sign's footprint including outlines and eyes.
- **Entry.** «Fra CSV» on the start page, «Lag skilt fra CSV …» under Mange skilt in the inspector, and «Eksporter via CSV» in the export dialog all open the workflow where the project left off.
- Output: one 3MF per plate or per sign, with a manifest.

#### The CSV workflow (Sivert, 2026-10-06, sections 24 to 35)

«Fra CSV» is a workflow, not a window. Nothing is generated while the user is still setting up the data. Since 2026-10-08 (phase 9, spec §11) it has **three tabs**: Importer, Koble and Generer. The separate Master button is gone; the master is the canvas between Koble and Generer and has no tab (a slim tray under the canvas shows the tabs, a «Du designer masteren» label and Lukk). Tabs that cannot be reached yet are dimmed with the reason. «Eksporter via CSV» in the export dialog keeps its name and opens the workflow where the project left off.

1. **Importer.** Read a file or pasted text (first line is the column names; at most 1000 rows, 2 MB). The content is an editable selection table: a **box on each column heading** takes the column forward or leaves it out (a column left out controls nothing and is hidden in Koble), a **box on each row** does the same for the row, «Velg alle / Velg ingen / Snu utvalget», Shift-click for a range, search over every cell and a filter on all / chosen / not chosen. Click a cell to correct it. Only what is ticked goes on (the rows are rendered 100 at a time).
2. **Koble.** Only the chosen columns are listed, each with one drop-down for what it controls (§27): a **text field**, a **decoration field**, the **colour of a layer or outline** (the cell names a filament) or the **colour profile**. The mapping applies to every chosen row at once; rows are never connected one by one. **«+ Legg til egendefinert kolonne»** adds a column of our own, either **Dekor** or **Fargeprofil**; the cells are then chosen per row in «Verdier per rad» (a decoration from the gallery, or a colour profile), with «Alle valgte rader» to set one value for everyone first. The master gets one decoration to stand in for the others (placed beside the texts, 16 mm), and each row swaps it for its own. Colour profiles map by position (colour 1 in profile A is colour 1 in profile B), as before. The **example row** the master is made from is chosen here. «Lag masteren fra rad N» makes the master (once), «Legg inn manglende felt» adds fields later. No fourth mandatory step is added for the per-row values.
3. **Generer.** Before generating it is a short status: **N rader valgt**, **N design** (different combinations of decoration and colour profile) and either «Klar til å generere» or a short list of what is missing (no rows or columns, a decoration field the master lacks, an unknown colour profile, rows with problems). Rows with problems are listed with «Fjern fra utvalget», «Rett på masteren» and «Rett i radene». The two spacing settings live here. Pressing **«Generer»** makes the signs and **only then** shows the **production plates** in the same tab (they are not a step before generating): the plates sorted by filament combination with the real build plate view, and a table of name, decoration, colour profile, filaments and status per sign. «Fargeprofil for dette skiltet» changes the profile of one sign (it writes that row's cell, adding a «Fargeprofil» column when there is none) without touching the master or the other signs and without generating again. «Rediger dette skiltet» opens one sign in the editor and back with the changes kept as overrides on that sign only. «Generer flere rader» goes back to the status; «Last ned» builds the ZIP.

Projects saved with the six-step version open as before: the old `rader` and `plater` steps are read as Importer and Generer, and a project without `valgteKolonner` takes every column forward.

**Signs are never stored.** A sign is always built from the master, the row and its overrides, so a change to the master reaches every sign (§31). The work is kept in the project (`parametre.csvarbeid`: the table, the connections, chosen and generated rows, overrides, options and the furthest step reached) and is left out of templates.

**Colour profile column.** The colours of the master's own palette are swapped for the profile's colours in the same order (first for first). A colour with no counterpart gets the closest colour in the profile. A colour column for one layer still wins over the profile. An unknown profile name is a problem on that row, not a silent fallback.

**Master and instance overrides (§30, §31).** «Rediger dette skiltet» opens one generated sign on the canvas with all the usual tools and a banner in place of the tray. What is changed is kept as **overrides on that sign only**: one named property of one object, layer or outline (position, rotation, scale, visibility, text size, letter spacing, line spacing, font, alignment; for layers and outlines colour, height, visibility and, for outlines, gap and width). The sign is not a detached copy: the master and the row still build it, and only the properties with an override stay as they were set. Overrides are shown clearly: a badge on the sign, a list with «Master: 50 mm · Her: 47 mm», and «Tilbakestill til master» for one value or the whole sign. What cannot be an override (new or deleted objects, layers and outlines; the text itself, which comes from the CSV row) is listed when the user finishes, and is not kept.

**Production plates by filament (§33).** Signs are put on plates by the **actual filament ids** they need (the set, sorted, not the order of the layers and not how alike the colours look), so signs that need the same filaments share plates and signs that need others do not. The combination with most signs comes first. A plate starts a new plate when full; groups never share a plate.

**3MF (§35).** Each sign is its own build item with one object per part, and each part has its own colour from the filament list; nothing is merged into one mesh. A plate file gives the filaments the same slots as every other plate with the same combination (AMS slots first when set), and lists the filaments in the file's metadata. The manifest lists plate, row, colours, filament ids and the number of overrides.

## Lamp generator

The user should feel that they are **designing a lamp**, not filling in a configurator.

- **Parameters:** overall height, top and bottom diameter, profile curve (the silhouette, edited directly), wall pattern (ribs, twist, waves, facets, perforation) with density and depth, twist angle, wall thickness, light source (hardware profile, below), material and colour, surface finish.
- **Hardware profiles (Sivert, 2026-09-29):** the light source is a data-driven profile (`generatorer/lampe/maskinvare.ts`): Bambu Lab LED Lamp Kit 001, E27 holder, E14 holder, a user-defined round module, or no light source (open or closed bottom). Every dimension carries its provenance (`produsentoppgitt`, `uklar`, `vanlig-mal`, `designstandard`, `ukjent`, `fysisk-verifisert`) and its sources, and the editor shows it next to the number. Unconfirmed numbers are never shown as facts; a verified value is a data change.
- **Geometry follows the hardware.** A module sits in a recess in a solid base: recess (module + tolerance), optional retaining lip, floor, cable hole and an open cable channel under the lamp out through the back. Holders get a bottom plate with an adjustable hole. The module is drawn in the 3D preview as a plain cylinder at its real size (preview only, never exported).
- **Fitting mode for Lamp Kit 001:** shows «Bambu Lab Lamp Kit 001», its dimensions with their certainty and «Ikke fysisk verifisert» until a test print has proven the fit. Basic controls: fastening (tape or lip), recess depth, fit-test piece, show module. «Avansert passform»: tolerance, lip, cable hole, channel size, floor, measured module size. The **fit-test piece** exports only the recess, lip and cable route in a thin ring, so the fit can be checked before printing the lamp.
- **Hardware-aware checks** (geometric only): module does not fit the base, too little material around it, recess clamped by the lamp height, cable hole leaves no ledge, floor too thin, channel smaller than a known cable, lip below the module top or too wide, shade wall hits a module that stands up, module cannot pass down through the lamp, holder hole larger than the bottom, thin holder plate. The editor states that these checks say nothing about electrical safety and that a printed lamp is not certified or approved because a supported kit is selected.
- **Direct manipulation:** drag the top edge to change height, drag a silhouette point to change the profile, drag around the lamp to twist the pattern. Numeric fields stay available for precision.
- **Light behaviour:** a light on/off toggle in the preview shows how the pattern and wall thickness let light through (translucency approximated in WebGL); a day/night background switch.
- **Printability:** vase-mode compatibility, overhang limits and minimum wall thickness are enforced or warned about with plain explanations.
- Shares the workspace shell, history, units, export and order flow.

## Articulated dragon generator

Allowed to have more personality than the other tools while clearly being Designporten.

- **Parts:** body, head, horns, spikes, tail, wings, pattern, size, colours, details. Each part has a small set of pre-modelled variants designed to connect at fixed articulation joints, so every combination prints and moves.
- **Choice UI:** visual pickers (thumbnails of each variant) in a bottom tray; the dragon stays visible in 3D at all times and **changes live** as parts are swapped. Colours per part or per zone.
- **Size:** set in mm (overall length) with the joint tolerances scaled correctly; limits enforced.
- **Personality:** the dragon can wiggle or react when a part is swapped (off under reduced motion).
- Must stay consistent with the mascot direction: cute, slightly spiky, purple/dark blue/beige.
- Model parts are prepared by Designporten (not procedurally generated), so the generator needs the part library as an asset; see open question in the decision log.

## BuildForge

A shared build engine where **the user forms the expression and the engine protects the mechanics** (Sivert, 2026-10-03). Sivert's first brief is kept as [buildforge-handoff.md](buildforge-handoff.md); his **newer direction** of 2026-10-04, which makes BuildForge a general modular build engine, is [buildforge-handoff-2026-10-04.md](buildforge-handoff-2026-10-04.md). Where they differ, the newer one wins. This section records what is decided and built. Two product families:

- **Clicker:** a printed base with a seat for a bought mechanical keyboard switch, and a printed top on the switch's stem.
- **Modular build** (handoff 2026-10-04): a model is a graph of body parts joined at connectors, with one **Main Body**. Dragons, snakes, heroes, people and creatures are all built the same way from one library; there is no fixed figure structure. The 0.2 figure family (six fixed segments) is converted to this on read.

- **Status:** digital prototype. The mechanism profiles are trial profiles (`mx-lignende-prove` 0.1.0 for the switch, `figurledd-prove` 0.1.0 for peg joints, `kuleledd-prove` 0.1.0 for ball joints). Every number carries its certainty (common published value, trial value, design choice) and the editor and report show it. Profiles are marked «Ikke testet» until a test print has proven them; nothing is called printable, safe or production-ready, and «Bestill» is not offered.
- **Project:** `Dokument.parametre` holds the family (missing = clicker, so 0.1 projects still open), the decorative shapes, the template, the profile id + version and, for modular models, the parts (`kropper`: library component, name, kind, colour, mirrored, placement, connectors), the connections (`forbindelser`: two connector ends, a turn angle at the joint and, for ball joints, a bend and its direction), the Main Body (`rot`) and, once the model has a ball joint, the ball joint profile id + version (`kuleprofil`). Shapes are stored in their part's own frame. The mechanics are never stored in the project, so a hand-edited file cannot change them; stored data is validated at runtime (invalid numbers, duplicate ids, unknown parts or connectors, male-to-male connections, a connector used twice, loops and unknown profile versions are rejected, not repaired). A 0.2 figure becomes ten parts and nine connections with its shapes unchanged; nothing is rewritten until the user edits.
- **Geometry (hybrid):** decoration is signed distance fields (sphere, rounded box, cylinder, cone; union, sharp add, subtract and smooth union with a blend radius in mm), meshed by marching tetrahedra into closed meshes. The locked mechanics (switch seat, cross socket, top plate, joint pegs and sockets) are exact meshes from the profile, never voxelised. Decoration is cut back from protected zones and from below the build plate. Each part is exported as one part made of overlapping closed shells.
- **Checks:** for clickers, collision through the whole travel (the swept volume of the moving top against everything fixed, with the clearance from the profile and a stated error bound), anchoring, cut-back notices, subtractions reaching the locked part, and trial limits for the top. For modular models: every part is one piece holding its joint parts, no part is empty, no two parts overlap as placed, subtractions do not reach a joint, and parts not connected to the Main Body are a yellow notice (they print, but loose). Each finding has a rule id, the shapes it concerns, cause, consequence, fix and evidence level. Status is green / yellow / red, and grey («Beregner») whenever the shown result belongs to an older revision. Digital status and physical profile status are shown separately.
- **Connectors and joints:** a connector has a family (`svivel` = peg joint, `kule` = ball joint), a gender (male = peg or ball, female = hole or socket) and a role (neck, shoulder, hip, wrist, ankle, tail, wing, generic). Only same family and opposite gender connect, and a connector takes one connection. A part straight from the library fits any family and takes the family of the connector it meets; changing the joint type of a connection changes both connectors together. A peg joint turns about one axis; a ball joint also bends up to the profile's largest bend (25°) about the ball's centre. Turn and bend are stored on the connection.
- **Ball joint (trial):** an 8 mm ball on a 3.6 mm neck (male) snaps into a spherical socket (female) through a 7 mm mouth, with 0.2 mm radial clearance and a 1.6 mm wall. The mouth is a cone with its tip in the ball's centre, so the neck meets the rim at the same bend all the way out; the profile check requires the drawn bend plus 5° margin to stay below that limit. The ball's centre sits far enough from the joint face that the socket rim clears the male part at full bend. The female part is cut back along a cone (slope tan of the largest bend + 5°) instead of a plane; rotating it about the ball's centre by up to that bend then keeps it clear of the male part's plane cut, so the male side needs only the plane. The cavity and the space the neck swings through are kept free of the female part's decoration. A stored bend above the profile's limit is a red finding (BF-KULE-01). Nothing is test-printed: whether the ball snaps in, holds or breaks the neck is unknown. Pegs and sockets are only made where two parts are connected; open connectors print nothing. Around each joint the decoration of both parts is kept out of the partner's swing cylinder, so the parts stay clear as the joint turns. Clearance is checked between the two parts a joint connects; whether other parts hit each other while turning is not checked.
- **Placement:** the Main Body and each loose group keep their own position; every other part is placed from its parent by the connection (connector meets connector, axes opposed, turned about the joint axis). Each group stands on the plate. A part from the library with a side (arms, legs, wings) is mirrored automatically when it goes on the other side of its parent, so a right arm is the mirror image of a left one.
- **Editor layout (modular, handoff §2, §39–41, §50–52):** canvas first. There is no tool rail, and on wide screens the properties panel is closed by default; it floats over the right side of the canvas when asked for (the «Egenskaper» button in the top bar, or «Egenskaper» in the radial menu). Small screens keep the «Deler» / «Egenskaper» sheets. The check is a compact status on the canvas («✓ Modell OK», «⚠ 2 problemer», «● Kan ikke eksporteres», «Kontrollerer …») that opens the findings and always says the model is not physically tested; the bottom tray is only used by clickers. Colours: purple = selected, green = valid attach, replace or connected, red = invalid or a fault, grey or faded = outside what you are working on.
- **Editor (modular):** a new document opens **«La oss bygge en …»** as a carousel over the canvas (not a dialog), with Drage, Slange, Helt, Menneske, Skapning and Blank, each shown with a preview drawn from its own shapes; each start gives exactly one part, the Main Body. The clicker templates follow at the end of the carousel. The left panel has two tabs: **Bibliotek** (body-part cards with previews drawn from each part's base shapes, category chips and a search field) and **Modell** (the model tree: ★ Main Body with what hangs on it, then loose parts). Drag a part from the library into the view: fitting free connectors show, the nearest within reach is chosen and the part snaps to it with a preview; right-click or C during the drag switches to the part's next fitting connector («Kobling 2 av 3»); held over a part of the **same kind** it replaces that part; over another kind of part it snaps to that part's nearest fitting connector, or replaces it when nothing fits; over the empty plate it goes loose. Without dragging (keyboard, touch): choose the part, then a connector from the list or on the model, «Legg løst på platen» or «Bytt ut». Dragging a part on the plate moves its group and can snap a loose group to a connector. **Replace** keeps every connection the new part has a fitting connector for (same role first, then nearest), leaves the rest loose where they were, keeps the user's own shapes on the part and swaps only the base shapes. Click selects a part, **Shift+click** adds parts to the selection. The part panel has name, colour, connectors and Rediger / Bytt ut / Speil / Koble fra / Dupliser / Slett (the Main Body can be replaced, not deleted); its **Ledd** panel switches the joint to the parent between Pluggledd and Kuleledd and has sliders for turn and, for a ball joint, bend and bend direction. **Right-click** (a long press on touch, the menu key or Shift+F10 from the keyboard) opens a **radial menu** for what is under the pointer: a part (Rediger, Bytt ut, Speil, Dupliser, joint type, Koble fra, Egenskaper, Slett), several selected parts (Speil alle, Fjern valget, Slett), the empty plate (Legg til del, Vis modelltreet, Tilpass visning, Egenskaper, Start på nytt), and inside a part a shape (Flytt, Roter, Skaler, Dupliser, mirror, Egenskaper, Slett), a connector (hann/hunn, joint type, Koble fra, Egenskaper, Slett) or the empty view (Gå ut, Legg til form, Ny kobling, Skjul/Vis resten, Tilpass visning). Arrow keys go round the ring, Esc closes it. «Save Part» waits for accounts (§65) and is not shown. **Double-click** (double tap on touch, or Enter) goes inside a part: the view frames the part, the rest fades (or hides with «Skjul resten»), a breadcrumb shows where you are, and Esc goes back out. Inside, the left panel has **Former** (shapes and details attach to that part's surface) and **Koblinger** (the connector editor): the part's connectors show on it as points (filled = male, ring = female, green = connected); a connector can be added by clicking on the part's surface (it points straight out of it), renamed, switched between male and female (a connection on it is broken first, after «Dette vil bryte forbindelsen til …»; the other part is never changed), switched between joint types, disconnected or deleted. A part can have up to 12 connectors. Touch: hold a library card, then drag it into the view. Each action is one undo step. Handles move and turn a selected part with its group (G / R) or move, turn and resize a selected shape (G / R / S); arrow keys and fields remain the non-dragging alternative.
- **Editor (clicker):** as before: library (Kule, Avrundet boks, Sylinder, Kjegle; Øyne, Horn, Pigger, Ører), attachment points on the current surface, Enkel and Avansert on the same project, «Prøv klikk» (reduced motion shows the end position), one mirror relation across the YZ plane, handles, colour per body.
- **Export:** blocked while the check is red (the project can still be saved). Otherwise 3MF, one STL per part, and a JSON control report with the project revision, the exact profile and its status, units, each part's checksum and every finding. The switch is never in the files. Modular models carry a notice that the joints are not physically tested and the model is not tested as a toy.
- **Builds** run in a web worker; while one runs, newer requests replace older ones and stale results are dropped.
- **Not built yet** (handoff 2026-10-04 §65–67, later phases): Body Chains, Sub-part Groups and hierarchy inside a part, moving a connector by dragging it (it is placed by clicking on the surface), separate print orientation per part, «Save Part» / «Mine» and other accounts, cloud storage, sharing and licensing, snap fits, print-in-place joints, magnets and screws. Whether parts other than the two a joint connects hit each other while it turns or bends is not checked. Clothes, import, permanent or snap-in joints, poses, modular letters, stacked clickers and production hand-off from the first brief are also not built and not shown.

## Ecosystem

Skaperverksted is an ecosystem, not a page. Future generators could include vases, pots, egg cups, cans/containers, trays, articulated snakes and other configurable products.

**A generator is a plug-in** that provides:

1. its **parameter schema** or object types;
2. its **geometry builder** (parameters/objects → mesh), pure and testable;
3. its **tools and inspector sections** (UI contributions to the shared shell);
4. its **presets and thumbnails**;
5. its **product mapping** (how a design becomes an orderable item: product id, price rule input, material set).

Everything else (shell, canvas, grid, units, selection, history, 2D/3D views, material catalogue, printer profiles, export, order hand-off, autosave, accessibility) is shared. Adding a generator must not require redesigning Skaperverksted. None of the future generators are built now.
- **2D bygger ikke 3D (Sivert, 2026-10-08).** In a generator with both views, editing in 2D only touches the drawing: the 3D model is not rebuilt (`Arbeidsbenk.planleggBygg` does nothing while 2D shows, and marks the model `modellForeldet`). Opening 3D builds it at once with a progress bar over the view (`byggFremdrift`, reported by `byggModell(dok, fremdrift)`; Sign Forge reports per layer and yields between steps so the bar can paint). Export builds on its own. In 2D the status bar shows the size from `forelopigMal` (no build) and says that parts, volume and notices come when 3D opens; the Produksjon panel says the same.
- **Punkter på sideprofilen (Sivert, 2026-10-08).** The wall can get extra points: «Legg til punkt» (in the middle of the wall after the selected point) or a double-click on the curve (`settInnPunkt` splits the Bézier segment, so the shape does not change). The profile then becomes a hand-made one (`egendefinert`). Added points move freely sideways and up and down (and can widen the profile); the bottom and top anchors still only slide along their own edge. **The wall may go back down while it moves inwards** (Sivert, 2026-10-08: «gå nedover igjen så lenge det ikke skaper overheng»): a groove or ridge in the top. The mesher then makes ring-shaped slabs: at each height the layer is solid between the 1st and 2nd crossing of the curve, from the 3rd inwards, and so on (`skiveDeler`, `ekstruder`). Moving outwards (the inset shrinks) is still an overhang and keeps the material's overhang warning. A vertical wall gets a width (1.5 mm) when it gets a point. Not handled: a layer resting on a grooved top is checked against the top anchor's footprint only, not the groove. Instead the user is warned, with no rule that prevents a wrong profile (Sivert, 2026-10-08): a note in the Profil panel (`harSpor`) and the same warning in the export dialog's list («lager et spor i toppen»).
- **Ikonrunde 2.** The 24 round-2 icons are in `shell/ikonsvg/` and in the registry; they replace the temporary icons for shapes, hole and eye, decor gallery, outline, new layer, close/finish/repair path, save decor, panel chrome, help, «Følg laget» and the distribute buttons.

- **Sign Forge, samlet tilbakemelding fase 1 (Sivert, 2026-10-08).** Spec: `docs/design/sign-forge-tilbakemelding-2026-10-08.md`, plan: `/mnt/project-files/sign-forge-tilbakemelding/plan.md`. Fase 1 (små ryddinger): Fil- og Paneler-menyen lukkes ved klikk utenfor eller Esc (`shell/lukk-meny.ts`); markeringsrektangel velger objekter det berører (`beroererBoks`, ekte omriss, ikke bare boksen); Panorer-ikonet er fjernet (Mellomrom og midtknapp panorerer); «Bokstavavstand»; én «Tekst»-overskrift; Rotasjon rett under størrelse og «Behold proporsjoner» sist (en feil CSS-regel gjorde avkrysningen 14 px bred); fargeprøver er kvadratiske; klikk på lagnavn markerer alle objektene i et lag med flere objekter (et lag med ett objekt viser fortsatt lagets egenskaper); profilpunktene har fast diameter; lang profilhjelp fjernet; STL og 3MF har hover-tekst («Geometri uten fargeinformasjon» / «med fargeinformasjon») og eksportteksten lover ikke lenger automatisk filamentkobling.
- **Fase 2: absolutt tallscrubber.** Linjalen under et tallfelt er et vindu på tallinjen (`vinduStart` i `TallFelt`): en strek per steg (8 px), en stor per femte, og pilen står der verdien er, også etter at musen slippes. Dras pilen forbi enden, ruller skalaen. Skrives en verdi som havner utenfor vinduet, sentreres vinduet på den. Transform-panelet er kompaktert: rotasjon (↻) og et lås-symbol for «Behold proporsjoner» på én linje, uten forklaringstekst.
- **Fase 3: lagpanelet.** «Nytt lag» er et lite plussikon nederst i panelet og lager ett tomt lag rett over det valgte (menyen er borte; «Nytt tekstlag», «Nytt lag rundt teksten» og «SVG som ramme …» ligger i høyreklikkmenyen på et lag, SVG som pynt og Dekor er i verktøyskinnen). Hver rad har et drahåndtak med riller til venstre (to kolonner med prikker i CSS, ikke et nytt ikon), så øye, lås og søppel. Bare håndtaket dras. Lag kan flyttes opp og ned i stakken med en strek som viser hvor de lander (`flyttLagTil`), midt på en tekstgruppe legger dem inni som før, og omriss kan omorganiseres innenfor sitt eget lag (`flyttOmrissTil`). Sletting finnes på lag, objekt og omriss (Angre henter det tilbake). Underlag og omriss er rykket inn med en gren, tekstgrupper har egen bakgrunn, og selve teksten er fremhevet. Tekstfarge velges i lagpanelet og i Egenskaper; for et lag med én tekst setter det lagets farge, med flere får den teksten sin egen farge (`settObjektFarge`).
- **Fase 4a: Innstillinger og Prosjektinnstillinger.** «Innstillinger» i menylinjen (bare i verktøy med lys flate, nå Sign Forge) gjelder brukeren i denne nettleseren, ikke prosjektet: lys/mørk/standard modus og bakgrunn i editoren (seks ferdige gradienter og flate farger, pluss én egen farge som gir en gradient der horisonten har fargen). Valget lagres i `localStorage` (`shell/innstillinger.ts`), legges som CSS-variabler på verkstedets rot og leses av 2D-lerretet og 3D-visningen gjennom tokens, så begge følger med. Lyse bakgrunner gir mørk skrift og linjer på lerretet. Måleenheter: bare millimeter, og menyen sier at flere enheter ikke er laget ennå. «Prosjektinnstillinger» åpnes fra det lille tannhjulet ved overskriften i lagpanelet (og fra Innstillinger → Byggeplate og kanvas) og samler byggeplate (ferdige størrelser 180–350 mm eller egne mål, egen høyde), farger i bruk, fargeprofil, automatisk stabling og printlaghøyde. Egenskaper handler nå bare om det valgte objektet eller laget. «Lag skilt fra CSV …» flyttet fra Egenskaper til Fil-menyen. Smale skjermer: menyene i menylinjen legges under linjen (de ble klippet av sideveis rulling).
- **Fase 4b: kontekstlinje, hjelpesøk og brukerfelt.** Under menylinjen ligger en kontekstlinje (`ui.Kontekstlinje`, eget rutenettområde `kontekst`) som alltid er der i Sign Forge og viser det aktive verktøyet eller utvalget kan gjøre. Velg: ikoner for justering (venstre, midt, høyre, topp, midt, bunn) og fordeling, valg av referanse (Utvalg, Plata, Linje), og for ett objekt «Lag» (flytt til lag eller løs ut av gruppen, det tastaturvennlige alternativet til å dra), «Legger til/Kutter» og fremst/bakerst i laget. Hull: sirkel, firkant, trekant eller sekskant (`FormKilde.hullform`, kan også endres på hullet i Egenskaper). Mangekant: antall sider. Paint: bredde, profil og Smooth (flyttet fra den flytende linjen over lerretet). Penn: lukk bane, fullfør åpen bane, ferdig. Justér-panelet er borte; hjelpelinjene ligger i et eget Hjelpelinjer-panel (lagrede arbeidsrom med Justér mister bare det panelet). «Lag og rolle» er fjernet fra Egenskaper: fargen står i et eget Farge-panel, CSV-feltene i «Til CSV» (venter på CSV-omleggingen i fase 9). Et lite hjelpesøk (`shell/hjelpesok.ts`, svarene i `signgen/hjelpeemner.ts`, også øverst i Hjelp-vinduet på smale skjermer) gir korte svar på «hvordan gjør jeg …». «Logg inn» er en merket plassholder uten krav om innlogging. Ikonene for justering er midlertidige funksjonsglyfer (se MANGLER.md).
- **Fase 5: historikk som tidslinje og tre eksportknapper.** Historikk-panelet og Produksjon-panelet er fjernet (lagrede arbeidsrom mister dem, og arbeidsrommet «Produksjon» er borte). Historikken ligger nederst som en smal tidslinje (`Tidslinje.tsx`, i bunnbrettet som deles med CSV-flyten): ett lite ikon per redigeringssteg etter navnet på steget, nåværende steg markert, tilbakeførte steg nedtonet, klikk går tilbake eller frem (samme som Angre og Gjør om). Det er ikke full parametrisk historikk: tidligere steg kan ikke redigeres. Eksporter / Bestill har tre knapper rett under platebildet, i denne rekkefølgen: «Last ned» (meny med 3MF og STL, med korte forklaringer: «Geometri med fargeinformasjon» / «Geometri uten fargeinformasjon»), «Eksporter via CSV» og «Legg i handlekurven». Knappene vises bare når verktøyet har dem (BuildForge og lampen har ikke CSV). Merknader-listen er uendret, og det står fortsatt at handlekurven bare sender en forespørsel uten pris. Faktaene som lå i Produksjon-panelet (mål, deler, volum, farger) står i eksportvinduet. 3MF gir ingen garanti om filamentplasser; det står ikke lenger i teksten.
- **Fase 6: profil-ikoner, tekstjustering og font-bibliotek.** «Veggen» i Profil-panelet er én rad med åtte ikonknapper (rett, bue ut, bue inn, S-kurve, trapp, avrundet kant, knekk, egendefinert). Hvert ikon tegner selve kurven fra den samme profilbyggeren som lager veggen (`byggProfil` og `samplerProfil`), så ikonet og resultatet ikke kan komme ut av takt; egendefinert er stiplet. Legg til punkt, Gjør glatt og Fjern punkt er ikonknapper (navnet står som etikett og tips). Tekstjustering er tre ikonknapper (midlertidige tegn, se MANGLER.md). Ved siden av fontvelgeren ligger en «Aa+»-knapp som åpner Google Fonts-biblioteket. Fontvinduet har søk øverst, viser hver font med navnet i selve fonten (liten forhåndsvisningsfil fra Fontsource lastes for de 20 radene som vises; får den ikke lastet, står navnet i vanlig skrift), og blar 20 om gangen med Forrige og Neste. Uten søk vises alle familiene i alfabetisk rekkefølge. Forhåndsvisningen og selve fontlisten er ikke testet mot det levende nettet fra byggemiljøet (kall er mocket i testene).
- **Fase 7: farger og dekor.** Fargeprofil-panelet er kompakt: prosjektets farger som kvadratiske prøver (klikk én for å flytte eller fjerne den; tallet er plassen i profilen, som CSV bruker), profilene som en rad med små fargestriper, og en **+** som åpner «Lag profil»: fargeprøver som flervelges (hake og plassnummer), navn og «Lag profil», som lager og bruker profilen. Prosjektets farger er forhåndsvalgt, så «lagre fargene jeg har» virker som før. Filamentregister (produsent, materiale, egne filamenter), grupper og redigering ligger under **Avansert**; standardflyten krever dem ikke. En SVG-form med egen farge beholder nå plassen i laget (rett etter vektoren, ikke sist) og rollen (legg til / kutt), lås og synlighet; før kunne den havne øverst i listen og miste kutt-rollen. **Dekorgalleriet** er en emoji-velger: en rad med temaer (symboler, natur, dyr, kjøretøy, sport og spill, Dine egne; hvert tema vises med ett av sine egne ikoner), søk, og et rullende rutenett. Holder du over et dekor, kommer to valg: «Sett inn» (hele) og «Velg deler» (åpner delvelgeren med bare dekorets deler; har det bare én del, sier galleriet det). Gjelder også egne dekor. **Lagre dekorelement** i kontekstlinjen lagrer de markerte vektorene (ikke tekst, hull eller kuttere) som ett dekor med fargene sine under Dine egne; det lagres som omriss, ikke som de opprinnelige redigerbare kurvene (punktet er markert «Vurdering» i spesifikasjonen). Lisens: `public/skaperverksted/dekor/` har NOTICE og Apache-teksten, og galleriet lenker dit; lisensen til hvert enkelt ikon er ikke kontrollert mot opphavspersonen (samlingens lisens sier at noen ikoner har sin egen lisens)., og «I tekstlaget» eller «I eget lag» velger hvor det legges. Ikke bygget: egne kategorier (det finnes ingen innlogging ennå; egne dekor ligger i nettleseren under Dine egne).
- **Fase 8: Paint-senterlinje og Mønster-verktøy.** Senterlinjen til et Paint-strøk har nå redigerbare punkter: de firkantede punktene på linjen flyttes ved å dra (ett drag er ett angretrinn), **Alt + klikk** på linjen setter inn et nytt punkt, dobbeltklikk, Delete eller ikonet «Fjern valgt punkt på senterlinjen» fjerner det (minst to punkter blir igjen), og ikonet «Legg til punkt på senterlinjen» legger ett midt i det lengste stykket. Bredde, breddepunkter, Smooth og tupp bevares fordi omrisset bygges på nytt fra kilden. Punktene bruker samme ikoner som punktene i en vanlig vektor (legg til, fjern); det er ikke et felles redigeringsverktøy, for en strek har en senterlinje og ikke et omriss å redigere. Dobbeltklikk på et strøk åpner derfor ikke lenger omrisset (det ville gjort strøket til en vanlig vektor og mistet bredden); «Gjør om til vektor» i egenskapene gjør det fortsatt, bevisst. Breddepunktene på kanten har forrang når de ligger nær et senterlinjepunkt. **Mønster** ligger i verktøylinjen (ikon midlertidig, se MANGLER.md; ingen hurtigtast): marker vektorene som skal gjentas, velg verktøyet, og kontekstlinjen viser valgene. Mønsteret går enten **i en retning** (antall kopier, avstand, retning i grader) eller **langs en bane** (en annen vektor: et Paint-strøks senterlinje, en vektors første bane eller en forms omriss; avstand 0 fordeler kopiene jevnt fra start til slutt, «Følg banen» dreier hver kopi etter banen), med ekstra dreining per kopi. Forhåndsvisningen viser omrissene til kopiene på lerretet. «Lag mønster» lager vanlige objekter i de samme lagene som originalene, som ett angretrinn; originalene blir stående. **Ikke bygget (markert «Vurdering» i spesifikasjonen):** et mønster som kan endres etter at det er laget (antall, avstand, bane), og todimensjonale rader og kolonner.
- **Fase 9: CSV i tre faner.** Importer, Koble og Generer erstatter de seks trinnene; den separate Master-knappen er fjernet, mens «Eksporter via CSV» og de andre knappene beholdes. Kolonner og rader velges med avkrysning i Importer, egendefinerte kolonner gir dekor og fargeprofil per rad i Koble, Generer viser først en kort status og viser platene først etter at «Generer» er trykket, og et enkelt skilt kan få annen fargeprofil eller åpnes i editoren uten at masteren eller de andre skiltene berøres. Detaljene står under «The CSV workflow». **Ikke bygget:** XLSX, og fargeprofilvalg per skilt utover profilnavnet i raden (egne farger på ett skilt gjøres i editoren som egne verdier).
